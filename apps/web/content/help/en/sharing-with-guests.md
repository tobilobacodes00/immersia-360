Guests never sign up. They scan a code, and their page opens in the phone's browser.

## On the booth

Right after the capture the booth shows the **result screen**: a QR code for the guest's page and a short code printed in words under it ("No camera? Go to _address_ and enter" and the code). The guest's link already works at that moment, even if the booth is offline; the page says **Your files are on their way** until the upload lands, and updates by itself. The result screen returns to the start screen after 45 seconds without a touch, or when you press **Next guest**.

Tabs under the QR code change what the code does:

- **Link** opens the guest's page.
- **WhatsApp** opens WhatsApp on the guest's phone with a message and their link ready to send.
- **Text** opens the messaging app with the same.

The booth never sees a phone number. And **Email me the link** lets a guest type an address; the link is sent from the server and the address is used for that one message and not stored. A session can be emailed up to five times an hour, and a booth device 120 times an hour.

## The settings

In the event's **Setup**, under **Sharing**:

| Setting                                   | What it does                                                                                                     |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **QR code on screen**                     | Show the code on the result screen.                                                                              |
| **Email**, **Text message**, **WhatsApp** | Offer those ways to send the link.                                                                               |
| **Smaller version for messaging**         | Make a lighter copy of 360 videos that sends quickly over WhatsApp (about 720p).                                 |
| **QR code on prints**                     | A small code on each print opens the digital copy. See [Print at the right size](help:printing-setup).           |
| **QR code at the end of videos**          | A 2-second end card, so a forwarded video still leads back to the download.                                      |
| **Ask guests for their details**          | An optional name and email form with a consent box. See [Guest privacy](help:guest-privacy).                     |
| **Contact for guests**                    | Shown once the event's files have expired, so guests can reach you.                                              |
| **Also copy to my cloud**                 | A copy of every file in your own Google Drive or Dropbox. See [Connect Google Drive](help:connect-google-drive). |

## The guest's page

The page opens fast, shows a poster picture first, and then the video, strip or GIF. A guest can:

- **Download** the file. Files are named with the event and a number if you turned on **Number the files**.
- **Save to Photos** on a phone, or **Share**.
- See the date the files will be removed: **Files are removed on …. Download anything you want to keep.**
- Delete their own files. See [Guest privacy](help:guest-privacy).

Several versions can be on the page: a video and a smaller video, a GIF, a photo strip, a boomerang, a short video.

## A guest without the QR code

Every capture has a six-character code, such as `K7M-2QX`, made of letters and numbers with no easily confused characters (never I, L, O, 0 or 1). The guest can type it at the address on the result screen, which is this site's `/c` page or your short domain, and arrive at their files. They can also search for it in the event gallery. See [Guest lost their QR code](help:faq-guest-lost-qr).

> [!TIP]
> Before the event, scan a real code with a phone and watch the page appear. The [setup check](help:setup-check) does exactly that, and also tests the upload path.
